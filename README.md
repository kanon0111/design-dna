# design-dna

Claude Code のプラグイン。MIT。

AI に「モダンでおしゃれに」と頼むと、**AI が良いと思うデザインの平均**が返ってくる。
平均には個性がないので、どれも似た顔になる。これはそれを避けるための仕組み。

要点はひとつだけ。**平均化が起きるのは「同じ属性に複数の参照が入る」時だけ**なので、
参照は基本1枚に絞る。そこから借りるのは**性格**（色・書体の組み合わせ・飾り・構図の考え方）で、
**寸法**（文字の大きさ・余白）は載せる内容の役割から決め直す。

> **実験中の試作です。** 道具として完成したものではなく、考え方と失敗の記録として読んでもらうのが一番役に立つ。
>
> - 動作確認は **Windows だけ**（Python 3.11 / Claude Code 2.1）。
> - 案の生成と本番ページの作成で **Claude Code を headless で呼ぶので、そのたびに利用量を使う**。
> - 採用した案から作る本番ページは HTML 1ファイル。中身は画面ごとに分けてナビで切り替える（縦に1本のスクロールにもできる）。
> - 参照の画像は同梱していないので、初回に自分で集める必要がある（数分）。

## 仕組み

### 1. 参照を集める（自動）

Godly / Lapa Ninja / Awwwards から候補を集める。全部で **227件**。
プールが「世間が良いと思うデザイン」なのは承知の上で、**選ぶのは人間**にする。
プールが一般的でも、フィルタが個人なら個性は残る。

### 2. 実測して分類する

サムネから**明度・彩度・コントラスト・色相の散らばり・エッジ密度・余白率**を測り、
k-means でまとめて centroid から名前を付ける。「〇〇系」を人が主観で付けると
そこに AI の平均が入り込むので、分類も命名も測定値だけから導出する。

| 系統 | 件数 | centroid の性格 |
|---|---:|---|
| 静かな余白 | 60 | ライト / ほぼ無彩色 / 余白たっぷり / トーナル |
| 明快コントラスト | 52 | ライト / ほぼ無彩色 / 余白ふつう / パンチ強 |
| 情報密度 | 41 | ライト / ほぼ無彩色 / 密 / パンチ強 |
| カラフル | 20 | ライト / 多色・高彩度 / 密 |
| ダーク・静 | 33 | ダーク / 差し色あり / 余白ふつう |
| ダーク・鮮色 | 21 | ダーク / 多色・高彩度 / 余白たっぷり |

**限界**: この6指標では構図が測れない。構図は軸の重みが最大（28）なのに画素からは読めないので、
分類は「色と明度と密度の系統」であって構図の系統ではない。構図は人が目で見て選ぶ前提。

### 3. 役割ごとに1枚ずつ選ぶ

| 枠 | 借りるもの | 必須 |
|---|---|---|
| 骨格 | 構図・余白のリズム | 必須 |
| 色 | 配色のロジック | 任意 |
| 文字 | タイポの態度 | 任意 |

1枚だと属性の掛け合わせができず、その1サイトの模倣になる。
多く選ぶと同じ属性に複数入って平均化する。**役割で分ければ3件でも平均は起きない。**

### 4. DNA を抽出する

選んだ参照の実物を見て、**両方に共通して現れた方針だけ**を不変条件にする。
「借りない部分」も明記する。参照固有の芸を移植すると滑るため。

### 5. 案は2つ。寄せる方向を変える

以前は自由度（0〜100%）で振れ幅を選ばせていたが、やめた（2026-09-26）。
欲しいのは「選んだデザインっぽく、内容に合わせて」の一点で、数字はそれを分かりにくくしていた。
0%は参照の寸法まで写して読めないページになり、100%は参照が効かず平均に戻る。

いまは案を2つ出す。どちらも参照の**性格**（色・書体の組み合わせ・飾り・構図の考え方・
階層の跳ね方）は同じだけ借り、**寸法**（文字の大きさ・余白）は内容の役割から決め直す（`polish.md`）。

| 案 | 寄せ方 |
|---|---|
| a | 参照の配置に近づける |
| b | 雰囲気のまま、内容が読みやすい組み方にする |

軸（構図・主役・地の明度・密度・コントラスト・階層の跳ね・装飾量）は、
参照から読み取った値の記録（`axis-values.md`）に使う。

**ルール4（重要）**: DNA に軸の**値**を書かない。書くとその軸は案をいくら変えても動かなくなる。
DNA に入れてよいのは「アクセント色を持たない」のような**方針**だけ。
（実際に「左寄せ非対称」「地は黒と生成り」を DNA に書いてしまい、
振れ幅をいくら上げても雰囲気が変わらない事故を起こしている。）

## 構成

**プラグイン側（全プロジェクト共通・読むだけ）**

```
.claude-plugin/plugin.json
commands/setup.md  commands/start.md  commands/reset.md
axes.md                    軸と取りうる値（参照の読み取りに使う）
polish.md                  仕上げの決まり（参照の性格は借り、寸法は内容の役割から決め直す）
refs/candidates/*.json     候補227件（URLのみ・26KB）
refs/metrics.json          実測値
refs/clusters.json         k-means の結果
web/picker.html            選別画面
web/compare.html           生成案の比較（データを読んで描く）
web/_redesign/             picker 自身のデザイン案
cache/                     収集した画像（gitignore・各自で取得）
tools/
  paths.py                 プラグイン側とプロジェクト側の線引き
  fetch_godly_sites.py  fetch_lapa.py  fetch_thumbs.py
  analyze_thumbs.py     cluster_thumbs.py
  build_picker.py       apply_style.py   make_redesign_images.py
  serve.py              jobs.py          reset.py
  isolate.py            layout.py        shoot.py（描画して撮り、文字を測る）
  grab_frame.py
```

**プロジェクト側（1回分・適用先ごと）**

```
<project>/.design/
  brief.md      この案件は何か（チャットで聞いた「作りたいもの」の要約）
  content.md    ページに載せる文言（案の生成はこれだけを文言の材料にする）
  target.json   本番のページを書く場所
  picks.json    選んだ ref
  dna.md        抽出した不変条件
  notes.md      参照ごとの読み取り
  ledger.md     生成台帳
  gen/          生成した案（サーバは /gen/ で配信）
  runs/         過去の生成案（reset で退避される）
```

`examples/cafe/` が適用先のサンプル。Cafe Little Leaf のページと、
曖昧な指示から出した旧3案（比較対象）が入っている。

## 使い方

```bash
git clone https://github.com/kanon0111/design-dna.git
```

Claude Code のスキルとして、**ホームに1回置けば全プロジェクトから呼べる**。
プロジェクトごとに入れる必要はない。

```powershell
# Windows（リポジトリの実体はどこでもよい）
New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\design-dna" -Target "<clone先>"
```

```bash
# macOS / Linux
ln -s "<clone先>" ~/.claude/skills/design-dna
```

次のセッションから自動で読まれる。外すときはリンクを消すだけ。

| コマンド | すること |
|---|---|
| `/design-dna:setup` | 初回だけ。依存を確認し、参照サムネを収集する |
| `/design-dna:start` | チャットで伝えた「作りたいもの」を受け取り、参照を選ばせ、案を生成し、採用案で本番のページを作る |

ふつうの使い方は、Claude Code のチャットで「こういうLPを作りたい」と内容を伝えてから
`/design-dna:start` を呼ぶこと。picker が開くので参照を選び、出てきた2つの案から
「この案で実装する」を押すと、そのまま採用案と伝えた内容で本番のページが作られ、タブがそのページに切り替わる。
この回の picker と比較画面はそこで閉じる。選び直すときは `/design-dna:start` をもう一度呼ぶ。
| `/design-dna:reset` | 1回分をリセットして選び直す |

ビルトインの `/design`（Claude Design のキャンバス）とは**別物**。

開発中は入れずに `claude --plugin-dir <clone先>` でも読める。

### 手で動かす場合

```bash
cd <対象プロジェクト>
python "<clone先>/tools/serve.py" 8000
```

**実行したディレクトリが適用先**になり、結果は `<project>/.design/` に書かれる
（`DESIGN_DNA_PROJECT` で上書き可）。http://localhost:8000/picker.html を開く。

系統6つ → 詳細 → ピンときた1枚をクリック（足すのは任意）。
作りたいもの（どんなページか）はチャットで Claude Code に話すもので、picker には入力欄も
おまかせも無い。picker はどのデザインにするかを選ぶだけ。

「決定」を押すと2つの案の生成ジョブが走り、終わると `/compare.html` に飛ぶ。

初回だけ、AI が実物を見るためのサムネが要る（`/design-dna:setup` と同じこと）。

```bash
pip install -r "<clone先>/requirements.txt"
python "<clone先>/tools/fetch_thumbs.py"
```

候補一覧・測定値・クラスタは同梱済みなので、収集し直す必要はない。
**参照の画像はリポジトリに含まれていない**（他サイトのスクリーンショットなので再配布しない）。

### 前提

Python 3.10+ と `opencv-python` / `numpy` / `Pillow`。
案の生成は `claude` コマンド（Claude Code）を headless で呼ぶので、
それも入っている必要がある。

## 現状と次

「収集 → 分類 → 選別 → 生成 → 比較 → 本番」が、picker と比較画面のボタンだけで通る。
別プロジェクトの空フォルダから呼べることと、生成が3案まで通ることは実地確認済み
（Windows / Python 3.11 / Claude Code 2.1）。

次にやること:

1. **採用した案を実サイトに適用する工程**。いまは `.design/gen/` に案が出るところまでで、
   実際のページの書き換えはしていない
2. 既存デザインシステムの検出と「拡張するか、ゼロからか」の分岐を実装で固める
3. 生成した案と最終形の差分を回収して DNA に還す
4. Windows 以外での動作確認（いまは Windows でしか動かしていない）

## 参照画像について

**このリポジトリに参照デザインの画像は1枚も入っていない。**

入っているのは `refs/candidates/*.json`（各CDNのURLと名前の一覧）と、
そこから測った `metrics.json` / `clusters.json` だけ。画像は
`tools/fetch_*.py` で**各自が自分の手元に集める**（`cache/` は `.gitignore` 済み）。

収集先には利用条件がある。godly.design の robots.txt は
`Content-Signal: search=yes, ai-train=no` を掲げている。集めた画像を再配布しないこと。
`fetch_lapa.py` は取得ページ数を引数で受け取るので、必要な分だけにすること。

そもそも**プールを配ることに意味がない**、というのがこの仕組みの立場でもある。
「フィルタが個人でないと個性は残らない」が前提なので、誰かが集めた227件を
同梱したらそれはその人の趣味の押し付けになる。集めるところから各自でやるのが正しい。

## 注意

- 案の生成は、**実際に Claude Code を走らせる**ので利用量を消費する（5〜10分）
- clone 先をクラウド同期フォルダ（OneDrive / Dropbox 等）に置くと、`.git` や
  `cache/` の同期で競合することがある。リンクで参照しているので、
  移すときは `~/.claude/skills/design-dna` を張り替えるだけで済む
- 生成した案は `.design/gen/` に**新しいファイルとして**出る。既存のページは書き換えない
