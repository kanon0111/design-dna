# 軸の値（参照から読み取れたもの）

`axes.md` の全7軸について、`picks.json` の参照から**実際に読み取れた値**を記録する。
固定される軸は、ここに書いた値を**積極的に再現する**（ルール5）。
「読み取れず」の軸は**固定できない**ので、案ごとに違う値を選ぶ（ルール7）。

参照は **l162 Ceremony Coffee Roasters 1枚のみ**（Lapa）。
素材は `cache/thumbs/l162.img`（756×1000）を今回あらためて
`_slices/l162-run06-full.png` と上下2分割に書き出して確認した。
Lapa のサムネは**ページ全体ではなく上部の切り抜き**で、写っているのは
ナビ／ヒーロー／商品段／セージの帯の途中まで。それより下は写っていないので、
ページ全体を根拠にする軸は断定できない。

ref が1枚なので、各軸の出どころは自動的に l162 に一意（ルール6は自明に満たす）。
`hint` は空なので、軸ごとの出どころ指定は無い。

| 軸 | 値 | 出どころ | 根拠 |
|---|---|---|---|
| 構図 | **読み取れず** | — | 可視範囲の中で揃っていない。ヒーローの見出しと商品段の2枚は左の柱に揃うのに、ナビはロゴ中央＋左右分割、右カラムの `Freshest of the Fresh` とセージの帯は中央揃え。ページ上部1/6程度しか写っておらず、どちらが支配的か決められない |

## 今回（自由度30% / 2案）の固定と解放

`request.json` の予算は 30。`axes.md` ルール2 に従い、**案ごとに別の組合せへ割り当て直した**。

- **構図（28）は「読み取れず」なので固定できない。** 値の無い軸を固定すると、
  再現されるのは参照ではなく適用先の元ページの値になる（ルール5の逆転そのもの）。
  よって構図は**案ごとに違う値を選び**、`variants.json` の `note` に明記する。
  これが `request.json` の `effectiveFreedom: 58`（= 30 + 28）の中身。
- **密度は「可視範囲のみ」だが値は取れている**ので、解放しない案では 疎 を再現する。
- 主役（色面）・地の明度（ライト基調）・コントラスト（低）・階層（中）・装飾（無）は
  読み取れているので、固定される案では**能動的に再現する**。手をつけないのは固定ではない。

| | a | b |
|---|---|---|
| 解放（予算内） | 地の明度20 ＋ コントラスト9 ＝ **29** | 主役22 ＋ 階層4 ＋ 装飾2 ＝ **28** |
| 構図 | 読み取れず → **中央対称** を選択 | 読み取れず → **対角** を選択 |
| 主役 | 色面（固定・再現） | **タイポ** |
| 地の明度 | **ダーク基調** | ライト基調（固定・再現） |
| 密度 | 疎（固定・再現） | 疎（固定・再現） |
| コントラスト | **高（パンチ）** | 低（固定・再現） |
| 階層の跳ね | 中（固定・再現） | **極端** |
| 装飾量 | 無（固定・再現） | **テクスチャ** |

予算の使い方について: picker の既定配分は {装飾2＋階層4＋コントラスト9＋密度15}＝30 だが、
これは `ledger.md` の run-04/a と完全に同じ集合なので避けた。また**密度に15を払うと
残り15では重い軸が1つも解放できず、2案が兄弟どころか双子になる**ため、
今回は密度を固定側に回し、a に地の明度、b に主役という重い軸を1つずつ配った。
a と b の解放集合は互いに素で、run-01〜05 のどれとも一致しない。

## 骨格枠に Lapa を選んだことの影響（据え置きの負債）

`axes.md` の「素材と軸の対応」どおり、Lapa の切り抜きからは一番重い軸（構図・28）の値が
取れていない。**自由度30%と言いながら、実際には 28 ぶんが参照ではなく生成側の裁量で
決まっている**（実質58%）。構図まで参照に従わせたいなら、フルページのある Godly の ref を
1枚足して `picks.json` に並べる必要がある。
