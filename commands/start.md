# design-dna : start

AI に「おしゃれに」と頼むと**良いデザインの平均**が返る。平均には個性がないので
どれも似た顔になる。これはそれを避けるための仕組み。

**ビルトインの `/design` とは別物**。あちらは Claude Design のキャンバス。
こちらは参照の選別と、そこからの案の生成。混同したら、この文章が読めているほうが design-dna。

やり直したいときは `/design-dna:reset`。

## 前提: 作りたいものはチャットで聞く

利用者はふつう、先にこのチャットで「こういうLPを作りたい」「この資料をページにしたい」と
話してから、このコマンドを呼ぶ。**それがこの回の依頼の本体**。
picker に作りたいものを書き直させない（picker は読むだけで、入力欄は無い）。

流れはこう。利用者がチャットに戻って指示し直す場面を作らない。

```
チャットで「作りたいもの」を聞く（このコマンドの前の会話 + 引数）
   ↓  brief.md（何を・誰に・どう見られたいか）と content.md（載せる文言）に書く
picker を開く → 利用者が参照を選んで「決定」
   ↓  隔離環境で案を2つ生成（a＝参照の配置に近い / b＝雰囲気のまま内容に合わせる）→ compare.html
利用者が「この案で実装する」を押す
   ↓  サーバがそのまま Claude Code を起動し、採用案 × content.md で本番のページを作る
そのタブが出来上がったページに切り替わる。この回の picker / compare は閉じる
```

選び直したくなったら、利用者はこのコマンドをもう一度呼ぶ（2. で picker を開き直す）。

## 1. 作りたいものを掴む

このコマンドより前の会話と、コマンドの引数を読む。そこに書かれていることが正。

- **何を作るか**（LP・紹介ページ・資料をWebにしたもの など。出すのは HTML 1ファイル。既定では中身を画面ごとに分けて切り替える）
- **誰に向けて、どう見られたいか**
- **載せる内容** — 利用者が書いた文言・資料・箇条書き・参照してほしいファイル

会話に「作りたいもの」が見当たらないときだけ、**チャットで**短く聞く。
既存のページを作り直す依頼なら、そのページの文言を材料にしてよい。

あわせて、プロジェクトに**既存のデザインシステム**があるかを見る
（`tokens.css` / `theme.*` / `tailwind.config.*` / `design-system/` / `ui/` / Storybook /
`assets/` のブランドフォント）。

| 状況 | やること |
|---|---|
| **既存のデザインシステムがある** | その語彙を**拡張する**。トークン・コンポーネント・密度に合わせる。自分の DNA を上書きしない。何に合わせたかを1行で言う |
| **ゼロから** | 以下の流れに進む |

既存アプリに別の DNA を被せるのは改善ではなく破壊。ここは最初に宣言する。

### 書き出すもの

**`<project>/.design/brief.md`** — 1〜3行。案の生成に「この案件について」として渡る。
**picker には出さない。** picker はデザインを選ぶだけの画面で、作りたいものの欄もおまかせも無い。
「誰に向けた何で、どう見られたいか」を利用者が読む言葉で。ファイル名やフレームワーク名を並べない。

**`<project>/.design/content.md`** — ページに載せる文言を、上から出る順に。
案の生成はこれ**だけ**を文言の材料にする（無いと既存の index.html から拾う）。

```markdown
# 見出し（ページの主題）
リード文

## セクション名
本文 / 箇条書き
```

- 利用者の言葉をなるべくそのまま使う。資料や箇条書きを渡されたら、その中身を落とさない
- 足りない部分を自分で書き足したら、その行の末尾に `<!-- 下書き -->` と付ける
- SNS リンクや架空の実績など、**依頼に無い内容を足さない**
  （画面を切り替えるためのナビは 4. で作るので、content.md には書かない）

本番のページはボタンから起動される別の Claude Code が作り、**このチャットは見えない**。
チャットで聞いたことのうち、ページに効くものは brief.md と content.md に全部書いておく。

**`<project>/.design/target.json`** — 最後に本番のページを書く場所。

```json
{"out": "index.html", "structure": "pages",
 "pages": [
  {"id": "home",  "label": "トップ",   "sections": ["#"]},
  {"id": "team",  "label": "チーム",   "sections": ["チームのミッション", "メンバー"]},
  {"id": "works", "label": "取組み",   "sections": ["今ホットな取組み"]}
 ]}
```

`structure` はページの並べ方。案の段階から効く（compare に並ぶ案も同じ並べ方で作られる）。

| | |
|---|---|
| `pages`（既定） | 画面を分け、ナビとボタンで切り替える。1つの HTML の中で `#id` で切り替わる |
| `scroll` | 上から下へスクロールする1枚。利用者が「縦長の LP」「1枚でスクロール」と言ったときだけ |

`pages` は画面の分け方。**ここで決めておく**と、どの案も同じ分け方で作られて見比べやすい。

- `sections` は content.md の `##` の見出し（`"#"` は冒頭の `#` とリード文）
- 1画面目はページの主題。そのあと、読む人が知りたい順に4〜6画面
- 短い節は隣とまとめる。1画面が長くなりすぎる節（取組み3件など）は1画面に1つの話にする
- `id` は英小文字、`label` はナビに出す短い名前

利用者が場所を言っていればそれ。言っていなくて `index.html` が空いていればそこ。
**既にあるファイルは上書きしない**（埋まっていたらサーバが `index-2.html` のように番号を足す）。

書いたら、brief と content.md の要点、画面の分け方、出力先を**チャットで3〜6行で見せる**。
推測で埋めたところは推測だと言う。直したいと言われたらファイルを直してから進む。

## 2. picker を開く

```
python "${CLAUDE_PLUGIN_ROOT}/tools/serve.py" 8000
```

**プロジェクトのルートで**バックグラウンド実行する。実行したディレクトリが適用先になり、
結果は `<project>/.design/` に書かれる（`DESIGN_DNA_PROJECT` で上書き可）。
すでに 8000 番が動いていたら `http://localhost:8000/api/brief` の `project` を見て、
このプロジェクトでなければ別のポートで立てる。

http://localhost:8000/picker.html をブラウザで開く（Windows なら `start ""` で）。

前の回で採用まで済んでいると、picker と compare は「採用済み」の画面で閉じている。
選び直しのために呼ばれたので、開く前に採用だけを外す（参照の選択と作ったページは残る）。

```
python "${CLAUDE_PLUGIN_ROOT}/tools/reset.py" --reopen
```

利用者には、picker で何をすればいいかを1〜2行で伝えて手を離す:
系統6つ → 詳細 → ピンときた1枚をクリック（足すのは任意）。

「決定」を押すと2つの案の生成ジョブが走り、終わると `/compare.html` に飛ぶ。
自由度や案の数を選ぶ欄は無い（2026-09-26 に廃止。振れ幅は案a / 案b の寄せ方で出す）。

## 3. 案の生成（picker が起動する。ここでは何もしない）

生成は `tools/isolate.py` がつくる隔離環境の中で走る。既存のコードは見せず、
参照画像・配置・`content.md` の文言（見出しの階層つき）・軸・画面の分け方・
仕上げの決まり（`polish.md`）と確認用の `shoot.py` だけを渡す。

案は参照の**配置と性格**を借り、**寸法**（文字の大きさ・余白）は content.md の階層から決め直す。
書いたら `shoot.py` で描画して撮り、文字サイズを測って、見て直す。

## 4. 本番のページを作る（compare が起動する。ここでは何もしない）

compare.html で「この案で実装する」を押すと、サーバが `.design/decision.json` を書き、
書き出し先（`target.json` の `out`。埋まっていれば番号を足す）を決めて、
プロジェクトの中で Claude Code を起動する。指示は `tools/jobs.py` の `implement_prompt`。
採用案の性格（色・書体・装飾・構図・階層の跳ね方）は変えずに、content.md の内容を採用案の型で足し、
`polish.md` に従って寸法を磨き、`shoot.py` で描画して見て直す。

できるとそのタブが `http://localhost:8000/project/<out>` に切り替わり、
その回の picker / compare は「採用済み」の画面になる（serve.py も request / decision を受けなくなる）。

利用者がチャットに戻って「できた？」と聞いたら、`.design/decision.json` の `out` を見て、
そのファイルがあれば場所を伝える。作成に失敗していたら、compare を開き直せばもう一度押せる。

## 守るべきこと

`${CLAUDE_PLUGIN_ROOT}/axes.md` を読むこと。特に:

- **ルール4** — DNA に軸の**値**を書かない。書くとその軸は案をいくら変えても動かなくなる。
  DNA に入れてよいのは「アクセント色を持たない」のような**方針**だけ。
  （「左寄せ非対称」「地は黒と生成り」を DNA に書いて、
  振れ幅をいくら上げても雰囲気が変わらない事故を実際に起こしている。）

平均化が起きるのは「**同じ属性に複数の参照が入る**」時だけ。だから枠を役割で分ける。
1枚だけだとその1サイトの模倣になり、多く選ぶと平均になる。

## 書き込んでよい場所

| | |
|---|---|
| 書いてよい | `<project>/.design/` の中 |
| 書いてよい（4. だけ） | `target.json` の `out` に書いた本番のページ。既存ファイルは上書きしない |
| 読むだけ | `${CLAUDE_PLUGIN_ROOT}/`（参照プール・軸・picker） |

参照プールは全プロジェクト共通なので、絶対に書き換えない。

## 初回だけ必要なこと

参照プールに画像キャッシュが無いと、AI が実物を見て選べない。

```
python "${CLAUDE_PLUGIN_ROOT}/tools/fetch_thumbs.py"
```

候補一覧・測定値・クラスタはプラグインに同梱されているので、収集し直す必要はない。
参照を増やしたいときだけ `fetch_lapa.py` → `fetch_thumbs.py` →
`analyze_thumbs.py` → `cluster_thumbs.py` → `build_picker.py` の順に回す。

## やり直す

```
python "${CLAUDE_PLUGIN_ROOT}/tools/reset.py"
```

`.design/` の1回分だけを初期化する。生成済みの案は `.design/runs/run-NN/` に退避され、
参照プールには触らない。
